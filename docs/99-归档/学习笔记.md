> **历史记录** · 原始学习笔记（方法论沉淀），非项目现状描述。

- 流程：
  - 提前定义内容：
    - 把模糊的目标清晰化：明确 输入、范围、约束、产物和验收条件
    - 把隐性知识变成可发现上下文：主动更新知识库
    - 判断需求中哪些由Agent实现，哪些由Workflow实现
    - 风险边界
  - 业务入口：
    - 身份校验（PW / SSO -> token）
    - 租户隔离
    - 权限分配（IAM）
    - 输入安全检查和风险分级（风险大的人工审批）
  - LOOP 
    - 装配上下文
      - 方法论：
        - 把角色和目标钉死：长时间调用不跑偏
        - 选：这一圈模型真正需要哪些历史信息？不相关的工具结果别全带上。避免注意力涣散
        - 压：长的 Observation 先摘要再入上下文，2000 行日志压成 3 行结论。
        - 截：超过阈值时，把早期的对话压缩成一段摘要（Auto-Compact），给关键状态留出空间。
        - 结构化组织：否则模型会"自我污染"——用前面错的中间结论去影响后面判断。
      - 内容：
        - 原始目标：From状态
        - 历史对话（选、压、阶段）
        - 当前状态：From状态
        - 必要信息：From RAG、记忆？
        - 可用工具：动态分配
        - 约束
    - 模型路由：
      - 根据某些条件自动调用对应模型
    - 约束：
      1. 权限与身份层：基于 IAM 的物理隔离 -- 不直接把数据库密码或全权 API Key 给模型，而是通过身份访问管理（IAM）系统，为 Agent 分配一个具备“最小权限”的临时凭证。
      2. 工具调用层：Schema 校验与参数过滤 -- 在 Agent 调用工具（Function Calling）的中间层，增加一层强类型校验和逻辑预审。
      3. 执行流程层：幂等键与状态机约束 -- 通过确定性的流程引擎（Workflow）来管理 Agent 的动作序列，防止重复执行或跳步。
      4. 安全合规层：Human-in-the-Loop (HITL) 审批流 -- 将高风险动作的执行权限从 Agent 手中收回，改为“提交申请”模式。
    - 工具调用：
      - 执行工具前先做check
      - 给它哪些工具：只给真正需要的，并不是越多越好，过多，Agent会频繁用错
      - 什么时候用哪个：该查的时候查，不该查的时候别瞎查
      - 工具结果怎么喂回模型：30条搜索结果别原样塞回去，先提炼再喂
    - 记忆与状态
      - 状态：
        - 每轮调用的状态，没有这个，Agent不知道哪些动作已经做过了
        - 不应该存放上下文中，要外化到文件系统（日志等长期介质）
      - 记忆：必须分层
        - 任务状态：写到文件，任务结束就归档
        - 会话中间结果：当论用完就扔
        - 长期记忆：写在常驻配置，每次调用都注入上下文（Claude Code 里的 CLAUDE.md、Cursor 里的 .cursorrules）
        - Session：这次会话发生过什么；
        - Task State：任务现在执行到哪里；
        - Memory：跨任务复用的稳定经验；
        - Artifact：已经生成的计划、文件、报告和代码；
        - Trace：系统实际上执行了什么。
    - 异常系处理：
      - 重复动作检测
      - 处理重试
      - 设置停止条件
      - 并在关键节点请求人工确认
    - 预算：预算触顶直接结束
      - 已经转了几步？（步数预算，通常 15-50 步封顶）
      - 累计花了多少 Token / 多少钱？（成本预算）
      - 跑了多久？（时间预算）
  - 业务出口：
    - 审批
    - 终止和收敛：
      - 让模型明确输出done:true
      - 用其他的规则和检查器验证结果
    - 交付
  - 工具层 MPC Skill：
    - 身份传递与最小权限：IAM
    - 工具发现与版本管理：硬编码确认，以免幻觉调用。
    - 参数校验和返回值结构：调用参数中间层校验
    - 敏感数据脱敏：
    - 高风险动作审批：HITL
    - 超时、重试、幂等和补偿：幂等键和状态机
    - 调用日志和审计证据。
  - Trace
    - 模型版本
    - 提示词版本
    - 上下文来源
    - 工具：名、参数、返回
    - 状态变化
    - Token、延迟
    - 重试
    - 最终结果
  - 系统监控评估
    - 成功率
    - 正确失败率
    - 延迟
    - 成本
    - 人工接管率
