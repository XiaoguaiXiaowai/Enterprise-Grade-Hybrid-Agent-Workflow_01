# 部署手册

> 状态：现行 · 最后校验：2026-08-18 · 校验方式：符号级 + 实测（docker compose config）
> 目标：本地 Docker 起全套 + 生产单机（阿里云）上线 + 运维要点。
> 拓扑与并发模型见 [高并发与部署架构.md](../02-架构设计/06-高并发与部署架构.md)；环境变量全量见 [配置清单.md](配置清单.md)。

## 1. 部署拓扑

```
Browser ──► Nginx（唯一入口）
              ├─ /      → web:3000（Next.js）
              └─ /api/  → app:8000（FastAPI；WS 升级头 + proxy_buffering off）
```

- `docker-compose.yml`：开发拓扑（app expose 8000、web expose 3000、nginx 80:80 同源入口）；
- `docker-compose.prod.yml`：生产拓扑（app 绑 `127.0.0.1:8001`、web 绑 `127.0.0.1:3000`，仅本机可达，由主机 nginx 反代——**容器不直接暴露公网**）；
- 生产站点配置：`deploy/nginx/playground.conf`（HTTPS 443 + Certbot、登录/seed 限流 `limit_req`、反代 8001/3000、SSE 关缓冲 + WS 升级）。

## 2. 本地 Docker 部署

```bash
cp .env.example .env          # 配置 OPENROUTER_API_KEY（可选）
docker compose up -d --build
# 访问 http://localhost/ （nginx 80 入口）
```

- 可选 Ollama：启用 `docker-compose.yml` 中注释的 ollama 服务，并设 `OLLAMA_BASE_URL=http://ollama:11434/v1`；
- 初始化演示数据：`docker compose exec app python scripts/seed_demo.py`（生产环境用 `init_prod.py` 建账户，见 §4）。

## 3. 生产部署（阿里云单机）

### 3.1 首次上线

```bash
git clone git@github.com:XiaoguaiXiaowai/Enterprise-Grade-Hybrid-Agent-Workflow_01.git /opt/git/enterprise-agent-workflow
cd /opt/git/enterprise-agent-workflow
cp .env.example .env          # 填真实密钥：SECRET_KEY / OPENROUTER_API_KEY / GITHUB_MCP_TOKEN / SEED 相关
bash scripts/deploy.sh        # 构建镜像 + 起 docker-compose.prod.yml
```

- 主机 nginx 安装 `deploy/nginx/playground.conf`（HTTPS 证书 certbot 管理）；
- 生产必须设置 `APP_ENV=production`（禁用演示 seed）并运行 `python scripts/init_prod.py --username X --password '强密码' --role admin` 建首个账户。

### 3.2 CI 自动部署

`.github/workflows/deploy.yml`：push main → ① `docs-check` job（`scripts/check_docs.py` 文档静态校验，**失败阻断部署**）→ ② SSH 部署（`git reset --hard origin/main` + `bash scripts/deploy.sh`）。前置配置见该文件头部注释（GitHub Secret `DEPLOY_SSH_KEY`、服务器 Deploy Key、服务器 `.env`）。

| 操作 | 命令 |

## 5. 运维要点

- **健康检查**：`GET /health`（app 存活）；nginx `proxy_pass http://app:8000/health` 已配；
- **日志**：容器 `docker compose logs -f app`；函数级日志 `LOG_DIR`（默认 `logs/`，`APP_LOG_LEVEL=info` 开启）；
- **MCP 故障**：`GET /api/mcp/servers` 看连接状态；`scripts/diag_mcp_stdio.py` 诊断 stdio 拉起失败；`POST /api/mcp/servers/{name}/disconnect|connect` 故障演练；
- **模型不可用**：主用失败自动降级 Ollama → 离线 reader（[配置清单.md](配置清单.md) 优先级规则）；
- **限流**：`deploy/nginx/playground.conf` 已对 `/api/auth/login` 与 `/api/auth/seed` 配 `limit_req`（5r/m），防爆破；
- **扩容方向**：见 [高并发与部署架构.md](../02-架构设计/06-高并发与部署架构.md) 阶段 2/3 roadmap（PG/Redis/独立 worker/多副本）。

## 6. 验证清单（部署后）

| 检查项 | 命令 |
|---|---|
| 容器状态 | `docker compose ps` |
| 后端存活 | `curl localhost:8000/health`（或反代域名 `/health`） |
| 登录 | `curl -X POST <入口>/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"..."}'` |
| 前端 | 浏览器访问入口，走完 登录 → 建单 → 审批 → 回放 |
| 文档门禁 | `python scripts/check_docs.py`（CI docs-check 同款） |
