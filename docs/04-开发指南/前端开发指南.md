## 1. 技术栈与目录

- **框架**：Next.js 14（`web/package.json`：`next ^14.2.35`、`react 18.3.1`），App Router。
- **渲染模式**：所有页面文件首行 `"use client"` —— 纯**客户端渲染 SPA**（页面间跳转用 `next/navigation` 的 `useRouter` / `next/link`），无服务端数据获取；登录态、数据全部在浏览器侧通过 `web/lib/api.ts` 直连后端。
- **语言/构建**：TypeScript（`web/tsconfig.json`）；`web/next.config.mjs` 仅配置 `output: "standalone"`（Docker 镜像用）。
- **样式**：单文件 `web/app/globals.css`（暗色主题 + 组件类：`.card`、`.badge`、`.chat-*`、`.trace-*` 等），无 CSS 框架。

## 2. 各页面功能与对应后端 API

> 路由前缀：后端所有 API 挂在 `/api/*` 下；下文「调用」列的函数均导出自 `web/lib/api.ts`。

### 2.1 登录页 `/login`（`web/app/login/page.tsx`）

| 功能 | 调用 | 后端端点 |
|---|---|---|
| 登录（默认填入 `admin`） | `login` | `POST /api/auth/login` |
| 展示演示账户密码（非生产） | `seedInfo` | `GET /api/auth/seed-info` |
| 已登录跳转 | `getToken` | —（localStorage 判断） |

登录成功后 `login` 把 `token` 与 `user`（含 role）写入 localStorage，`useRouter().push("/tickets")`。网络错误（`fetch failed` 等）会翻译成「无法连接服务器」。

### 2.2 工单台 `/tickets`（`web/app/tickets/page.tsx`）——核心页面

| 功能 | 调用 | 后端端点 |
|---|---|---|
| 分页列表 + 状态筛选 + 搜索（300ms 防抖） | `listTicketsPaginated` | `GET /api/tickets?page=&page_size=&status=&q=` |
| 新建工单（弹窗表单） | `createTicket` | `POST /api/tickets` |
| 触发 Agent 执行（后台入队，不阻塞 UI） | `runTicket` | `POST /api/tickets/{id}/run` |
| 详情 + 对话（2s 轮询） | `getTicket` / `getConversation` | `GET /api/tickets/{id}` / `GET /api/tickets/{id}/conversation` |
| 实时事件流（WS） | `subscribeTicketWS` | `WS /api/tickets/{id}/ws?token=…` |
| 多轮追问（pending_confirm / failed 状态可发） | `sendMessage` | `POST /api/tickets/{id}/messages` |
| 客户确认完成 | `confirmTicket` | `POST /api/tickets/{id}/confirm` |
| 取消工单（未决审批一并作废） | `cancelTicket` | `POST /api/tickets/{id}/cancel` |
| 删除工单（仅 admin 卡片上按钮） | `deleteTicket` | `DELETE /api/tickets/{id}` |

页面要点（读码核实）：
- 列表筛选 Tab → 后端 `status` 逗号集合：待审批=`awaiting_approval`、处理中=`created,triaged,gathering,agent_running,running`、已完成=`done,archived`、失败=`failed`。
- 活跃工单开启 **2s 轮询**（`getTicket` + `getConversation` 并行），列表仅在状态变化或每 10 次轮询（≈20s）时兜底刷新。
- 建单成功**立即** `subscribeTicketWS` 订阅实时流，随后 `runTicket` 触发执行；`stage` 事件（相关性→重写→分类）以「⏳/✅/❌」流式展示，`model_call(kind=final)` 与 `deliver` 渲染为助手消息。
- 时区：后端存 UTC（`"YYYY-MM-DD HH:MM:SS"` 无时区后缀），前端按 UTC 解析后换算 `Asia/Shanghai` 展示。

### 2.3 审批台 `/approve`（`web/app/approve/page.tsx`）

| 功能 | 调用 | 后端端点 |
|---|---|---|
| 待审批 / 历史记录分页列表 | `listApprovals` | `GET /api/approvals?page=&page_size=&status=pending\|history` |
| 通过 / 驳回 | `approve` | `POST /api/tickets/{ticket_id}/approve` |

- 待审批 Tab 开启 **3s 轮询**（`setInterval`，切到历史 Tab 时暂停）；用请求序号 `seqRef` 丢弃过期响应，防翻页/轮询竞态。
- 决策后后端入队 `resume_ticket`，Agent 恢复执行或按驳回调整；页面提示「已通过/已驳回」。

### 2.4 Trace 回放 `/traces/[id]`（页面文件：`web/app/traces/[id]/` 目录下的 `page.tsx`）

| 功能 | 调用 | 后端端点 |
|---|---|---|
| 工单全链路执行记录 | `getTraces` | `GET /api/traces/{ticket_id}` |

- 每次模型调用 / 工具调用 / 状态变迁一行，点击展开详情（模型、提供方、提示词版本、IO JSON、状态迁移、延迟、token）。
- 顶部统计卡：调用次数、总延迟、总 token、模型集合、工具集合；`context_source` 区分 `assemble` / `tool` / `agents_sdk` / `agents_sdk_final`。

### 2.5 指标 `/metrics`（`web/app/metrics/page.tsx`）

| 功能 | 调用 | 后端端点 |
|---|---|---|
| 监控指标（时间段 / 全部历史） | `getMetrics` | `GET /api/metrics?start=&end=&all=` |

- 预设区间：本月 / 近 7 天 / 近 30 天 / 今年 / 全部历史；也支持自定义日期范围。
- 渲染：6 张汇总卡（工单总数、成功率、正确失败率、平均延迟、总成本、人工接管率）+ 纯 SVG 趋势图（柱=每日工单数、折线=成功率）+ 每日明细表。数据源 `app/metrics.py`（每次工单结束自动记录）。

### 2.6 知识库 `/kb`（`web/app/kb/page.tsx`）

| 功能 | 调用 | 后端端点 |
|---|---|---|
| 文档列表 | `listDocuments` | `GET /api/kb` |
| 上传（.txt/.md/.pdf/.docx，≤10MB） | `uploadDocument` | `POST /api/kb/upload`（multipart FormData） |
| 删除 | `deleteDocument` | `DELETE /api/kb/{doc_id}` |

上传/删除后自动重建 FTS 与向量索引（`app/kb.py:rebuild_indexes`）；页面仅 `operator / admin` 可见（导航按角色隐藏）。

### 2.7 MCP 工具面 `/mcp`（`web/app/mcp/page.tsx`）

| 功能 | 调用 | 后端端点 |
|---|---|---|
| server 状态列表 + 各 server 工具清单 | `listMcpServers` / `getMcpServerTools` | `GET /api/mcp/servers` / `GET /api/mcp/servers/{name}/tools` |
| 连接 / 断开（故障演练）/ 热刷新 | `mcpConnect` / `mcpDisconnect` / `mcpRefresh` | `POST /api/mcp/servers/{name}/connect\|disconnect\|refresh` |

- **3s 轮询**刷新状态；表格展示每个 `{server}__{tool}` 的 risk / 允许角色 / `param_schema.required` / 描述（来自 `app/mcp/config.py` 映射白名单）。

### 2.8 导航 `web/components/Nav.tsx`

- 全部角色可见「工单台」；`operator / admin` 额外可见「审批台 / 指标 / 知识库 / MCP 工具面」。
- 监听 `storage` 事件实现多标签页登录态同步；「退出」清 localStorage（`clearToken`）并回 `/login`。

## 3. API 客户端封装（`web/lib/api.ts`）

单一客户端文件，所有后端调用都从这里走：

- **基址**：`const API = process.env.NEXT_PUBLIC_API_URL || ""`（构建期注入；空 = 同源 `/api`）。
- **Token 持久化**：localStorage 键 `token`（`getToken` / `setToken` / `clearToken`）；登录用户信息存 `user`（`setUser` / `getUser`，含 `role` 供按角色渲染）。
- **请求封装** `req<T>(path, init)`：自动带 `Content-Type: application/json`，有 token 时附加请求头 `X-Auth-Token: <token>`；**401 → 清 token + 跳转 `/login`**；非 2xx → 抛后端 `detail`（FastAPI 错误体，422 时取校验数组首条 msg）。
- **登录特例** `login()`：不走通用 `req()`——登录失败的 401 是「凭据错误」语义，不能触发清 token 跳转；单独解析 `detail` 后抛「用户名或密码错误」。
- **SSE 兼容**：`subscribeTicketWS` 基于 WebSocket（见 §4）；文件头部注释保留「封装 fetch、token 持久化、SSE」字样，但当前代码中事件流已全部走 WS（`/events` SSE 端点后端仍保留，见 §4.2）。
- **上传** `uploadDocument`：`FormData` 直传（不走 JSON `req`），手动带 token。

主要导出（按用途分组）：`login` / `seedInfo` / `me`；`createTicket` / `listTickets` / `listTicketsPaginated` / `listAllTickets` / `getTicket` / `deleteTicket` / `getConversation` / `runTicket` / `sendMessage` / `closeTicket` / `confirmTicket` / `cancelTicket`；`getApprovals` / `approve` / `listApprovals`；`getMetrics`；`listMcpServers` / `getMcpServerTools` / `mcpConnect` / `mcpDisconnect` / `mcpRefresh`；`getTraces`；`subscribeTicketWS`；`listDocuments` / `uploadDocument` / `deleteDocument`。

## 4. 实时通道

### 4.1 WebSocket（现行方案，唯一推荐）

- **服务端**：`app/api/tickets.py:ws_events`，端点 `WS /api/tickets/{ticket_id}/ws`。浏览器 WebSocket 无法自定义 header，故 token 经 **query 参数** `?token=…` 传入；校验失败按关闭码 4401/4404/4403 拒绝。
- **协议**：先回放该工单全部历史事件（`app/daos/tickets.py:list_events`），随后服务端 0.3s 轮询 `list_events_after` 增量推送；每条消息为 JSON：`{type, at, payload}`。
- **前端**：`subscribeTicketWS(ticketId, onEvent)`（`web/lib/api.ts`）返回**取消订阅函数**（关 WS）。`https:` 时自动用 `wss:`；配置了 `NEXT_PUBLIC_API_URL` 时 WS 指向该源，否则同源。
- **事件类型**（`web/app/tickets/page.tsx` 的 `eventToMsg` 逐类渲染）：`created` / `user_message` / `system_message` / `model_call`（仅 `kind=final` 展示）/ `tool_call`（不展示）/ `hitl`（等待审批提示）/ `deliver`（完成卡片）/ `state_transition` / `stage`（首轮流水线进度）/ `closed` / `cancelled` / `confirmed` / `reject_followup` 等。
- **使用场景**：工单台在**新建工单成功后**订阅，运行期间实时刷新对话与状态；离开时 `stopStreamRef.current?.()` 取消。

### 4.2 SSE 兼容端点（deprecated）

- `GET /api/tickets/{ticket_id}/events`（`app/api/tickets.py:events`）：基于长轮询的 `StreamingResponse`（`text/event-stream`），先回放再 0.3s 轮询增量；`token` 经 query 兼容 `EventSource`。
- **前端当前未使用**（工单台已改 WS）；保留仅为兼容旧客户端。新功能一律走 WS，后续版本可移除。
- 注意：该端点需要反代层对 SSE **关闭缓冲**（`proxy_buffering off`，见 `nginx.conf` / `deploy/nginx/playground.conf`）。

### 4.3 轮询节奏汇总（实测读码）

| 场景 | 节奏 | 位置 |
|---|---|---|
| 活跃工单详情+对话 | 2s | `web/app/tickets/page.tsx`（`setInterval` 2000ms） |
| 工单列表兜底刷新 | 状态变化即刷，否则每 10 tick（≈20s） | 同上 |
| 审批台待审批 Tab | 3s | `web/app/approve/page.tsx` |
| MCP 工具面状态 | 3s | `web/app/mcp/page.tsx` |
| 服务端 WS 增量轮询 | 0.3s | `app/api/tickets.py:ws_events` / `events` |

## 5. 本地开发与构建

### 5.1 环境变量

- `web/.env.example` 仅一个键：`NEXT_PUBLIC_API_URL`。
  - **默认空 = 同源 `/api`**：浏览器请求发到前端同源路径，由 Nginx 反代到后端（生产/演示标准形态）。
  - 本地裸跑后端时按注释填 `NEXT_PUBLIC_API_URL=http://localhost:8000`（复制为 `web/.env.local`）。
- 该变量是**构建期**内联（`process.env.NEXT_PUBLIC_*`），改后需重启 `next dev` 或重新 `next build`（Dockerfile 中经 `ARG NEXT_PUBLIC_API_URL` 注入）。

### 5.2 常用命令（在 `web/` 下）

```bash
npm install          # 安装依赖（package-lock.json 已锁定）
npm run dev          # 开发服务器 http://localhost:3000（热更新）
npm run build        # 生产构建（standalone 产物输出到 .next/standalone）
npm run start        # 以 standalone 产物启动（镜像内用 node server.js）
```

### 5.3 与后端联调（重要：CORS 实测结论）

- 后端**未注册 CORS 中间件**（`app/main.py` 无 `CORSMiddleware`）。实测：跨源预检 `OPTIONS /api/tickets`（带 `Origin` + `Access-Control-Request-*`）返回 **405**，且响应无 `Access-Control-Allow-Origin` 头 → **浏览器跨源直连（`localhost:3000` → `localhost:8000`）会被同源策略拦截**（带 `X-Auth-Token` 头或 JSON POST 必触发预检）。
- 因此**推荐联调路径是「同源反代」**：
  - `docker compose up -d --build`：Nginx `:80` 统一入口（`/` → web:3000，`/api/` → app:8000），浏览器访问 `http://localhost` 即可，`NEXT_PUBLIC_API_URL` 留空。
  - 或本地起 `nginx` 使用根目录 `nginx.conf` 同源代理。
- 若必须裸跑跨端口联调：要么自行给 FastAPI 加 `CORSMiddleware`（或本地反代），要么仅用 WS 通道（WebSocket 不受 CORS 限制）——**REST 调用仍会被拦截**。
- 后端启动：仓库根 `.venv/bin/uvicorn app.main:app --reload --port 8000`（详见 [快速开始.md](../00-项目概览/快速开始.md)）。

### 5.4 常见问题

- **登录后 401 跳回 /login**：token 无效/过期（会话默认 12h，见 [配置清单.md](../03-部署运维/配置清单.md) 的 `SESSION_TTL_HOURS`），或后端换了 `SECRET_KEY`。
- **页面数据不动**：检查 `NEXT_PUBLIC_API_URL` 是否指向可达后端（并注意跨源会被 CORS 拦截，见 5.3）；轮询类页面（tickets 2s / approve、mcp 3s）有延迟属正常。
- **WS 连不上**：反代需开启 `Upgrade`/`Connection` 头透传（`nginx.conf` 已配）；token 过期时服务端以 4401 关闭。
- **构建期改了 API 地址没生效**：`NEXT_PUBLIC_*` 是构建期内联，重启 `next dev` / 重新 `next build`。
- **`/traces/[id]` 无数据**：工单尚未运行过，或 Trace 已被删除（管理员删除工单会级联清除 traces）。
