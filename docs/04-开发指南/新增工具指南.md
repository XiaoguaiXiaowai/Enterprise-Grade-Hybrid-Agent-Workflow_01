# 新增工具指南（自研 skill 与 MCP 工具）

> 状态：现行 · 最后校验：2026-08-18 · 校验方式：符号级 + 行为实测
> 定位：Agent 能调用的工具只有两条新增路径——**自研 skill**（代码内实现，硬编码白名单）与 **MCP 工具**（外部 server + 映射声明）。两条路径最终都汇入同一条治理链：白名单 → RBAC 过滤 → 预算/去重 → 审计落库 → HITL 审批。
> 前置阅读：[能力-代码映射表.md](../01-核心功能/06-能力-代码映射表.md)（⑤ 工具层 / ⑩ MCP）；MCP 集成设计详见 [MCP工具集成.md](../01-核心功能/03-MCP工具集成.md)。涉及配置键一律引用 [配置清单.md](../03-部署运维/配置清单.md)。

## 0. 治理总览：一条链、两道入口

| 治理点 | 自研 skill | MCP 工具 | 强制执行位置 |
|---|---|---|---|
| 白名单 | `app/skills/registry.py` 注册表（未登记即拒绝） | `mcp_servers.json` 映射表（未声明即拒绝） | `app/skills/registry.py:invoke` / `app/mcp/config.py:load_config` |
| RBAC | `Tool.roles` 元组 | 映射项 roles | `app/skills/registry.py:tools_for_role` / `app/agents_tools.py:build_agent_tools` |
| 执行治理（预算/去重/落库/trace/事件/计步） | `app/agents_tools.py:_run` | `app/mcp/bridge.py:_invoke_mcp` | 两者同构 |
| 风险控制 | risk=high → needs_approval=True | 映射 risk=high → needs_approval=True | `app/agents_tools.py:_wrap_tool` / `app/mcp/bridge.py:_make_function_tool` |
| 脱敏 | `app/skills/masker.py` | `app/mcp/bridge.py:_sanitize`（复用 masker） | 工具函数内 / 桥接层 |

## 一、自研 skill：五步新增

下面以新增「查询机房温度」只读工具 `query_rack_temperature` 为完整示例，逐步照做。

### 第 1 步：实现工具函数

在 `app/skills/` 下新建模块（本示例文件名 `rack_temperature.py`），实现要点与现有工具一致：

- **参数校验在函数内**（白名单/格式），非法参数返回 `{"ok": False, "error": ...}`；
- **返回 dict**，成功为 `{"ok": True, ...}` + 业务字段（与 `app/skills/grant.py:grant_db_readonly` 同风格）；
- **敏感字段返回前脱敏**，用 `app/skills/masker.py:mask_principal` / `app/skills/masker.py:mask_secret`（参照 `app/skills/user_dir.py:query_user_dir`）。

```python
# 文件：app/skills/rack_temperature.py（新建）
"""只读工具：查询机房机柜温度（演示数据源）。低风险。"""
from .registry import register_tool
from ..tracelog import trace_call

# 演示数据源；真实场景替换为监控系统/传感器接口
_RACK_TEMP = {"A01": 24.5, "A02": 25.1, "B01": 31.8}


@register_tool(name="query_rack_temperature", risk="low",
               description="查询机房指定机柜的实时温度（只读）。")
@trace_call("tool.rack_temperature.query_rack_temperature")
def query_rack_temperature(rack: str) -> dict:
    rack = rack.strip().upper()          # 参数校验在函数内：规范化 + 白名单
    if rack not in _RACK_TEMP:
        return {"ok": False, "error": f"未知机柜: {rack}"}
    return {"ok": True, "rack": rack, "temperature_c": _RACK_TEMP[rack]}
```

> 说明：`@trace_call` 保留原签名（`app/tracelog.py:trace_call`），业务异常会打 exit 日志；`register_tool` 显式给 name 后不依赖函数名。

### 第 2 步：注册进白名单（硬编码注册表）

用 `app/skills/registry.py:register_tool` 注册。签名与缺省行为：

- `name=None`：缺省取 `fn.__name__`；
- `risk="low"`：low | medium | high；
- `roles=None`：缺省 `("employee", "operator", "admin")` 全员可见；
- `description=""`：缺省取函数 docstring。

现有工具定级参照（风险/角色语义必须对齐）：

| 工具 | risk | roles | 位置 |
|---|---|---|---|
| `search_kb`（知识库检索，只读） | low | 全员（缺省） | `app/skills/kb.py:16` |
| `query_user_dir`（用户目录查询，脱敏） | medium | 全员（缺省） | `app/skills/user_dir.py:13` |
| `grant_db_readonly`（开通只读账号，写操作） | high | `("operator", "admin")` | `app/skills/grant.py:33` |
| `revoke_db_readonly`（回收权限，补偿动作） | high | `("operator", "admin")` | `app/skills/grant.py:58` |

**验证方式**（仓库根目录）：

```bash
.venv/bin/python -c "from app.skills import rack_temperature, registry; \
t = registry.get_tool('query_rack_temperature'); \
print(t.risk, t.roles, registry.invoke('query_rack_temperature', {'rack': 'A01'}, ctx={}))"
```

预期输出：`low ('employee', 'operator', 'admin') {'ok': True, 'tool': 'query_rack_temperature', 'result': {...}}`。`app/skills/registry.py:get_tool` / `list_tools` / `tools_for_role` / `invoke` 全部只认注册表，未登记工具 `invoke` 返回 `{"ok": False, "error": "unknown tool: ..."}`（防幻觉调用）。

### 第 3 步：SDK 包装（让 Agent 能调用）

Agent 主链路（OpenAI Agents SDK）不直接执行注册表函数，而是通过 `app/agents_tools.py` 里的显式签名包装。在 `app/agents_tools.py` 追加：

```python
# app/agents_tools.py 追加（显式签名，与 registry 内参数一致）
def _query_rack_temperature(ctx: RunContextWrapper, rack: str) -> dict:
    """查询机房指定机柜的实时温度（只读）。"""
    return _run("query_rack_temperature", ctx, {"rack": rack})
```

并把 `_query_rack_temperature` 加入 `_SDK_TOOLS` 列表（`app/agents_tools.py:150` 附近）。

两条必须遵守的命名/装配规则：

- `app/agents_tools.py:_tool_meta` 用 `fn.__name__.lstrip("_")` 反查注册表 → **包装函数名必须是 `_<注册名>`**，否则 `app/agents_tools.py:build_agent_tools` 过滤不到；
- `app/agents_tools.py:_wrap_tool` 按注册表 risk 决定 `function_tool(needs_approval=...)`：**risk=="high" → needs_approval=True**，自动接入 SDK 原生 HITL 审批（`app/agents_tools.py:171`），工具内无需自行实现审批。

> 若只想让传统降级链路（LLMGateway 循环）用、不挂 SDK Agent，可跳过本步——降级链路直接经 `app/skills/registry.py:invoke` 执行。

**验证方式**：

```bash
.venv/bin/python -c "from app.agents_tools import build_agent_tools; \
print([t.name for t in build_agent_tools('employee', ['query_rack_temperature'])])"
```

预期输出：`['query_rack_temperature']`（角色不在 roles 元组内则装配为空列表）。

### 第 4 步：装配到 Agent（按职责挂载）

Agent 组在 `app/agents_defs.py:build_agent_group` 定义：TriageAgent 无工具，经 handoff（`transfer_to_knowledge_agent` 等 4 个）把工单分发到 KnowledgeAgent / IdentityAgent / ChangeAgent / CmdbAgent；每个子 Agent 只持有自己职责范围内的工具（按 `*_TOOLS` 列表装配，`app/agents_defs.py:25-35`）。

- 只读知识类 → 挂 KnowledgeAgent：`KNOWLEDGE_TOOLS = ["search_kb", "search_kb_direct"]` 追加 `"query_rack_temperature"`；
- 身份/权限类 → IdentityAgent（`IDENTITY_TOOLS`）；高风险写操作 → ChangeAgent（`CHANGE_TOOLS`）；MCP 外部工具 → CmdbAgent（`CMDB_TOOLS`，命名见第二节）；
- **只有新职责才需要新建 Agent**，并在 TriageAgent 的 `handoffs` 列表追加 `transfer_to_xxx_agent`（`app/agents_defs.py:80-85`）。

**关键副作用**：工具注册发生在模块 import 时。`app/main.py:16` 的 `from .skills import kb, user_dir, grant` 就是为「确保工具注册到注册表」——**新建 skill 模块后必须把新模块追加进该 import 行**（或保证被 agents_defs / agents_tools 链路间接 import），否则生产进程不注册。

**验证方式**：

- `.venv/bin/python scripts/smoke_agents.py` —— 真实链路（handoff + HITL）；
- `.venv/bin/python scripts/smoke_m2.py` —— M2 工具全链路冒烟（含 grant 高风险的 HITL 审批流）。

### 第 5 步：风险 / 角色定级 + 全链路验证

定级标准（与现有实例对齐）：

| risk | 判定标准 | 现有实例 |
|---|---|---|
| low | 只读、无敏感数据 | `search_kb` |
| medium | 只读但含个人信息/敏感字段（返回前必须脱敏） | `query_user_dir` |
| high | 写操作 / 权限变更 / 影响面大 | `grant_db_readonly` / `revoke_db_readonly` |

high 工具三件事必做（参照 `app/skills/grant.py`）：

1. **幂等**：重复调用不产生重复副作用（grant 已存在 active 授权则返回「幂等命中」）；
2. **补偿**：提供反向动作（`revoke_db_readonly` 回收）；
3. **HITL**：risk=high 自动 needs_approval=True（第 3 步），员工角色默认不可见（roles 收窄为 `("operator", "admin")`）。

**验证方式**（仓库根目录，全部可执行）：

```bash
.venv/bin/python scripts/run_all_tests.py   # 离线确定性：T08 未白名单工具被拒 / T09 RBAC / T10 重复动作
.venv/bin/python scripts/rbac_smoke.py      # 三角色可见范围（employee 默认只读低/中风险）
.venv/bin/python scripts/smoke_m2.py        # HITL 全链路（含审批/恢复）
```

## 二、MCP 工具：三步新增

MCP 工具是「实现外置、治理内嵌」：工具代码跑在外部 server，能不能被调、谁调、什么风险、要不要审批，全由 `mcp_servers.json` 映射表白名单决定。集成设计详见 [MCP工具集成.md](../01-核心功能/03-MCP工具集成.md)。

### 第 1 步：写 / 启动 MCP server

- **stdio 子进程**（本地）：参考 `scripts/mcp_servers/cmdb_server.py`（`build_server` 暴露 `query_asset` / `list_network_devices` / `update_asset_owner`）。`command` 必须是仓库内相对路径或绝对路径，**不允许跨目录**（`app/mcp/config.py` 校验）；
- **远程 streamable_http / sse**：如 `github`（`https://api.githubcopilot.com/mcp/`，`headers` 注入 `Bearer ${GITHUB_MCP_TOKEN}`）；
- 连接生命周期（懒连接/超时重试/健康检查）由 `app/mcp/servers.py:McpRegistry` 承担，本步不需要实现。

### 第 2 步：在 mcp_servers.json 声明工具映射

结构：`servers[]` 内每个 server 声明 `name` / `transport` / `command`（stdio）或 `url`+`headers`（远程），`tools` 为「工具名 → 治理映射」白名单。以下为真实 `cmdb.query_asset` 节选：

```json
{
  "servers": [
    {
      "name": "cmdb",
      "transport": "stdio",
      "command": ".venv/bin/python",
      "args": ["scripts/mcp_servers/cmdb_server.py"],
      "cwd": ".",
      "env": {"CMDB_DATA": "${CMDB_DATA}"},
      "tools": {
        "query_asset": {
          "risk": "low",
          "roles": ["employee", "operator", "admin"],
          "description": "查询 CMDB 服务器资产信息（只读）",
          "param_schema": {
            "type": "object",
            "required": ["hostname"],
            "additionalProperties": false,
            "properties": {"hostname": {"type": "string"}}
          }
        }
      }
    }
  ]
}
```

映射语义（`app/mcp/config.py` 校验，坏配置拒绝装载、不拖垮其它 server）：

- **未在 `tools` 声明的工具默认拒绝**（与注册表白名单同语义）——server 暴露 100 个工具，没声明就一个都装配不了；
- `param_schema` 是 **JSON Schema 子集**：`type` 必须 `object`，`properties` 内 `type` 只收 `string`/`number`/`integer`/`boolean`/`array`/`object`/`null`，`required` 为字符串数组，`additionalProperties: false`（`app/mcp/config.py:_validate_param_schema`）；
- `risk` / `roles` 字段语义与 `app/skills/registry.py:Tool` 完全对齐：`risk=high` → HITL；roles 缺省全员，敏感工具显式收窄；
- 密钥一律 `${ENV_VAR}` 占位（`headers` / `env`），配置加载时从进程环境展开，**不落 JSON、不进 git**（如 `${GITHUB_MCP_TOKEN}`，对应配置键 `GITHUB_MCP_TOKEN`）。

### 第 3 步：验证与装配

**验证方式**：

```bash
.venv/bin/python scripts/smoke_mcp_core.py   # 确定性冒烟（不依赖真模型）：白名单/装配/HITL/脱敏/落库/重复拦截/未映射拒绝
curl -s http://127.0.0.1:8000/api/mcp/servers -H "X-Auth-Token: <token>"          # operator/admin
curl -s http://127.0.0.1:8000/api/mcp/servers/cmdb/tools -H "X-Auth-Token: <token>"  # 映射后 risk/roles
```

- `GET /api/mcp/servers` 与 `GET /api/mcp/servers/{name}/tools` 需 `operator`/`admin` 角色（`app/api/mcp.py:36`）；
- 前端一屏可见外部工具面：`web/app/mcp/page.tsx`。

**装配**：MCP 工具统一暴露为 `{server}__{tool}` 全局限定名（双下划线分隔，`app/mcp/bridge.py:split_tool_name` 拆分），加到 `app/agents_defs.py` 对应 `*_TOOLS` 列表（如 `CMDB_TOOLS = ["cmdb__query_asset", ...]`，只读挂 KnowledgeAgent、写操作挂 ChangeAgent 的 `GITHUB_WRITE_TOOLS` 同理）。`app/mcp/bridge.py:build_mcp_tools` 自动构造 SDK FunctionTool 并走治理链（`_invoke_mcp`：预算 → 去重 → 调用 → 脱敏 → 落库/trace/事件）。

## 三、治理红线对照表

| 红线 | 自研 skill 怎么做 | MCP 工具怎么做 | 不守的后果 |
|---|---|---|---|
| 白名单 | `@register_tool` 登记，未登记 invoke 拒绝 | `mcp_servers.json` 显式声明，未声明拒绝装配 | 幻觉调用/越权调用直达外部系统 |
| 参数校验 | 函数内白名单/格式校验 | `param_schema`（JSON Schema 子集）调用前校验 | 脏参数入库/触发副作用 |
| 脱敏 | 返回前过 `mask_principal`/`mask_secret` | 桥接层 `_sanitize` 递归打码（同源 masker） | 个人信息/凭证泄漏进对话与 trace |
| 幂等 | 业务幂等 + `app/guards.py:is_duplicate` | 同左（全局限定名参与指纹） | 重复开通/重复写库 |
| HITL | risk=high → needs_approval=True | 映射 risk=high → needs_approval=True | 高危写操作绕过人工审批 |
| 审计 | `_run` 统一落 tool_calls/trace/ticket_events/计步 | `_invoke_mcp` 同构（context_source=mcp） | 不可追溯、不可回放 |

## 四、常见坑

1. **risk 定级过松**：写操作必须 `high`，否则绕过审批直接执行；`high` 又缺省 roles 全员 = 风险敞口。
2. **roles 缺省即全员可见**：employee 默认装配低/中风险只读工具；凡含个人信息或写语义的工具必须显式 `("operator", "admin")`。
3. **MCP 忘写 tools 映射**：工具「存在但不装配」——`GET /api/mcp/servers/{name}/tools` 核对映射后的 risk/roles 是否如预期。
4. **`server__tool` 双下划线约定**：`app/mcp/bridge.py:split_tool_name` 按第一个双下划线切成 `(server, tool)`；server 或 tool 名若含双下划线会错位解析，且全局限定名直接出现在 trace/tool_calls 落库中，命名必须可溯源。
5. **param_schema 写坏**：`type` 必须 `object`；属性 `type` 只收七种白名单值；`required` 必须是字符串数组；非法 schema 拒绝装载（启动即报错进日志），不会静默放行。
6. **SDK 包装函数名**：必须 `_<注册名>`（`_tool_meta` 反查规则），否则 `build_agent_tools` 过滤不到、Agent 拿不到该工具。
7. **新 skill 文件忘 import**：注册是 import 副作用；`app/main.py:16` 的 `from .skills import kb, user_dir, grant` 需追加新模块。
8. **降级链路与 HITL**：`app/mcp/bridge.py:ensure_proxies_registered` 只注册 `risk != "high"` 的 MCP 工具——高风险写操作强制走 SDK 链路的原生审批，传统文本降级链路不承接审批语义。
