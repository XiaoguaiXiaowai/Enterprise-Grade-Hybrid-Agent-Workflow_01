## 2. 后端分层地图（`app/`）

调用方向自顶向下：**API → 编排 → 智能（Agent）→ 模型 → 工具 → 数据**，可观测与支撑模块横切各层。

### 2.1 入口与 API 层

| 文件 | 内容 |
|---|---|
| `app/main.py` | FastAPI 应用入口：`lifespan`（建库/种知识库/播种账户/关闭时清理 MCP 连接）、注册 5 组路由、`/health`、请求级埋点中间件 `trace_requests` |
| `app/api/auth.py` | `/api/auth/login`、`/me`、`/seed-info`、`/seed`；登录（PBKDF2 校验 + 会话签发）、演示播种 |
| `app/api/tickets.py` | 工单核心路由：CRUD、`/{id}/run`、`/{id}/messages`（追问）、`/confirm`、`/cancel`、`/close`、`/conversation`、`/events`（SSE，deprecated）、`/{id}/ws`（WebSocket）、`/approve`、`/approvals` |
| `app/api/governance.py` | 治理路由：`/api/traces/{ticket_id}`、`/api/metrics`、`/api/approvals`、`/api/routes` |

| `app/deps.py` | FastAPI 依赖：`current_user`（解析 `X-Auth-Token`）、`require_role`（RBAC 守卫） |

完整路由清单见 `tmp/doc_consolidation/api_routes.txt`（仓库内已生成）或 `docs/04-开发指南/前端开发指南.md` 的页面对接表。

## 3. 一次工单请求的代码路径（真实函数链）

以下函数名均已逐行核实（见行号标注）；「📡」= 前端调用，「🧵」= 后台 worker 线程。

1. **建单** 📡 `POST /api/tickets`
   → `app/api/tickets.py:create_ticket`（L65）→ `app/daos/tickets.py:create_ticket`（L8）→ `app/daos/tickets.py:add_event`（L141，写 `created` 事件）→ 立即返回 ticket_id（不做同步 LLM 校验）。
2. **触发运行** 📡 `POST /api/tickets/{id}/run`
   → `app/api/tickets.py:run`（L135）→ `app/taskqueue.py:try_acquire`（L34，每工单互斥锁）→ `app/taskqueue.py:submit_ticket_job`（L53，入队 `run_ticket`，返回 `{"status":"queued"}`，不占用 HTTP 线程）。
3. **编排入口** 🧵 `app/orchestrator.py:run_ticket`（L171）→ `app/orchestrator.py:_run_loop`（L288）。
4. **首轮流水线**：仅 `created` 状态执行 `app/orchestrator.py:_entry_stages`（L179）：
   `app/classifier.py:relevance_check`（相关性）→ `app/classifier.py:rewrite_content`（重写，受 `PROMPT_REWRITE` 开关）→ `app/classifier.py:classify`（意图/风险分级，回写工单元数据）；每步经 `app/daos/tickets.py:add_event` 写 `stage` 事件供前端流式展示。
5. **状态机推进**：`app/state_machine.py:can_transition` 校验 → `app/daos/tickets.py:transition`（L110）走 `created → triaged → gathering`。
6. **准备执行**：`app/model_router.py:route` 选模型 → `app/llm_gateway.py:get_llm` 取网关 → `app/budget.py:Budget.start_for` 开预算 → `app/trace.py:new_req_id` 生成请求 ID → `app/context_assembler.py:assemble` 装配上下文 → `app/skills/registry.py:tools_for_role` 按角色过滤工具；另调 `app/mcp/bridge.py:ensure_proxies_registered` 注册 MCP 代理工具。
7. **主链路（SDK）**：`app/agents_runner.py:sdk_ok()` 为真时 → `app/agents_runner.py:run_sdk`（L243）→ 内部 `app/agents_defs.py:build_agent_group`（L38）组装 Agent 组、`app/agents_tools.py:build_agent_tools` / `build_mcp_tools` 挂工具 → 高风险工具触发 SDK 原生中断 → `app/agents_runner.py:_handle_interruptions`（L168）落审批 → 状态转 `awaiting_approval`；审批后经 `app/api/tickets.py:approve`（L386）→ `app/orchestrator.py:resume_ticket`（L112）→ `app/agents_runner.py:resume_run`（L277）恢复同一 run。
8. **降级链路（传统 LOOP）**：SDK 不可用（抛 `app/agents_runner.py:SdkUnavailable`）→ `app/orchestrator.py:_plan_and_execute`（L523）：`llm.chat` 出计划 → `_parse_tool_calls`（L33）解析工具调用 → 逐个 `app/orchestrator.py:_execute_tool`（L571）。
9. **工具执行治理**：`app/skills/registry.py:get_tool` + `invoke`（L50）→ 高风险先 `app/daos/approvals.py:request` 申请审批（`app/orchestrator.py:_NeedsApproval` 中断）→ 幂等检查 `app/guards.py:is_duplicate` → 调用后 `app/daos/tool_calls.py:record` 落库 + `app/trace.py:write` 写 trace + `add_event("tool_call")` + `budget.consume_step()`。
10. **收敛与指标**：回合结束 → `app/daos/tickets.py:transition` 到 `pending_confirm` → `app/orchestrator.py:_finalize_round`（L240，回写预算/`PROMPT_VERSION`/结论 + `app/daos/memory.py:append` 长期记忆）→ `app/orchestrator.py:_record_metrics`（L617）→ `app/metrics.py:record`（L47）。
11. **客户确认** 📡 `POST /api/tickets/{id}/confirm` → `app/api/tickets.py:confirm`（L234）→ `pending_confirm → done`（终态）。
12. **实时推送**：全程事件经 WS `app/api/tickets.py:ws_events`（L341，`/api/tickets/{id}/ws`）增量推送给前端（回放 + 0.3s 轮询）；`app/agents_trace.py:install` 把 SDK span 一并落库，`/api/traces/{ticket_id}` 可全链路回放。

> 流程图速记：`POST /api/tickets` → `create_ticket` → `POST /run` → `taskqueue.submit_ticket_job` → `orchestrator.run_ticket` → `_run_loop` → `_entry_stages` → `agents_runner.run_sdk`（或 `_plan_and_execute`）→ `registry.invoke` / MCP bridge → `trace.write` + `metrics.record`。

## 附：常见疑问

- **入口到底在哪？** 后端 `app/main.py`（`uvicorn app.main:app`），前端 `web/app/layout.tsx` + `web/app/page.tsx`。
- **Agent 代码在哪里？** 定义在 `app/agents_defs.py`，执行在 `app/agents_runner.py:run_sdk`，工具在 `app/skills/*` + `app/mcp/*`，提示词在 `app/prompts/agents.py`。
- **「传统链路」和「SDK 链路」是什么？** 两条并行实现：SDK 链路用 OpenAI Agents SDK（`run_sdk`），SDK 不可用时降级到 `_plan_and_execute`（手写 tool-calling 循环 + LLM 网关）；两者共用同一套工具治理（预算/幂等/审计/trace）。
- **数据都存在哪？** 业务数据在 `data/app.db`（SQLite，12 张表，见 `app/db.py`）；向量在 `data/vector-kb`（LanceDB）；文件级日志在 `logs/`。
