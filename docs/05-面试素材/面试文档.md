## 1. 一句话定位（开场必背）

> "我搭的是一个**企业级 Agent 收拢件（Harness）**：它不是一个'让 AI 更聪明的 Demo'，而是展示 **AI 如何被可靠、可控、可审计地接进企业业务**。我以 IT 工单为载体，把大模型当作'判断层'，把执行权交给确定性的流程、权限与审批。"

**三个关键词**（贯穿全场，反复用）：

- **可靠**（Reliable）：状态机、幂等、预算、停止条件 —— 不跑飞
- **可控**（Controlled）：IAM 最小权限、工具白名单、HITL 审批 —— 不越权
- **可审计**（Auditable）：Trace 全链路、监控指标 —— 出错能查

## 2. 30 秒电梯介绍（自我介绍用）

"我实现了一个企业 IT 工单处理系统，覆盖从**身份校验 → 智能入口分级 → Agent 循环 → 人工审批 → 客户确认 → 审计交付**的完整闭环。技术栈是 Python + FastAPI + SQLite（WAL）做后端 Harness，编排上**自研状态机**管治理、**OpenAI Agents SDK** 管 LLM 循环与多 Agent handoff（5 个 Agent、4 条 handoff）；LLM 主用 **OpenRouter**（OpenAI 兼容）⇄ **Ollama 兜底** ⇄ **离线 reader** 三级降级，前端 Next.js 14，单机 Docker Compose 部署。它把大模型的 8 类工程问题——上下文管理、模型路由、权限隔离、工具安全、HITL、预算、Trace、监控——全部落地成可运行代码，并在此基础上扩展了 **RAG 双路召回、MCP 外部工具面、高并发后台任务化**三条主线。"

## 3. Demo 演示脚本（10-12 分钟版）

> 准备：`docker compose up -d --build` 后访问 `http://<IP>/`；本地调试可 `uvicorn app.main:app --reload --port 8000` + `cd web && npm run dev`（`http://localhost:3000`）。
> **先跑播种**：`.venv/bin/python scripts/seed_demo.py`（幂等：账密/知识库/示例工单），演示账户 `admin` / `operator` / `employee` 密码**不再硬编码**，取 `SEED_USER_PASSWORD`（seed 默认 `demo-pass-2026`），用 `GET /api/auth/seed-info` 现场查看。

### 3.1 开场 · 首页/流程图（1 分钟）

- 打开根 README 架构图（或 [项目简介](../00-项目概览/项目简介.md) 图），强调"这是 harness 而非单模型应用"
- **话术**："这 11 条主线（8 大能力 + RAG/MCP/高并发）今天我会带你在真实工单里挨个走一遍。"

### 3.2 登录 · 身份与租户（40 秒）

- 用 `admin` 登录（密码见 `/api/auth/seed-info`），再快速展示角色概念（employee/operator/admin）
- **讲点**：不同角色装配到 Agent 的工具集不同（RBAC 在工具层生效：`tools_for_role` 过滤），租户 `tenant_id` 贯穿所有表

### 3.3 建工单 · 智能入口（1 分钟）

- 建一张**高风险**："给 u-1024 开通数据库只读账号"
- **讲点**：
  - 表单**只有标题/描述**——没有"风险/意图"下拉框；分级是 **run 阶段自动做的**：`_entry_stages` 流水线（相关性校验 → 内容重写 → 意图/风险分类），以 `stage` 事件流式推送进度
  - 相关性不通过 → 工单直接 `cancelled` + 拒绝文案，不进状态机（防无关请求浪费算力）

### 3.4 运行 · LOOP 与上下文装配（2 分钟）

- 点"运行"，响应立即返回 `{"status":"queued"}`（**入队即返，不占 HTTP 线程**），随后看 **WebSocket**（`/api/tickets/{id}/ws`）实时事件流：`created → triaged → gathering → agent_running`（前端另有 2s 轮询兜底；SSE 已 deprecated 仅作兼容保留）
- 讲点：
  - **上下文装配**：选/压/截——只带这一圈真正需要的（目标/状态/近 N 条历史/工具清单/约束/剩余预算），超阈值自动摘要（`_auto_compact`）
  - **模型三级降级**：OpenRouter 主用 → 失败自动切 Ollama → 均不可用回退离线 `reader`（现场没 key 也不翻车）
  - **工具白名单**：模型只能在注册表里选工具，不存在的工具直接拒绝

### 3.5 触发 HITL · 人工审批（2 分钟）

- Agent 规划调用 `grant_db_readonly`（高危工具）→ 工单进入 `awaiting_approval`
- 切到审批台，`operator` 看到待审单 → 点"通过"
- 讲点（核心，面试官最感兴趣）：
  - 三层安全约束：最小权限凭证 → 参数强校验 → 幂等状态机；HITL 是第四层"人接管权"
  - 高危动作执行权**从 Agent 手里收回**，改成"申请-审批"模式
  - SDK 原生 interruptions：`function_tool(needs_approval=True)` → 审批通过后 `Runner.run_sync(agent, state)` **从同一 RunState 恢复**（多 Agent handoff 后同样成立）；`RunState` 序列化落库（`approvals.run_state_json`），进程重启也能从 DB 恢复

### 3.6 流程终点 · 客户确认（1 分钟）

- 审批恢复后状态**不直接到 done**：经 `gathering → agent_running → pending_confirm`（待客户确认）
- 工单发起人点"确认完成"（`POST /api/tickets/{id}/confirm`）→ `done` → 归档
- **讲点**：收敛（Agent 认为做完了）≠ 完成（业务上确认做完了），两件事分开——这是 harness 区别于"聊天机器人"的关键设计

### 3.7 MCP 外部工具面（2 分钟）

- 建一张「查 CMDB 资产」工单 → run → triage 判定 → **handoff 到 CmdbAgent**（第 4 条 handoff：`transfer_to_cmdb_agent`）→ 调用 `cmdb__query_asset` → 返回资产信息
- 现场打开 `GET /api/mcp/servers`（或前端 `/mcp` 页）：展示 **cmdb / github 两个 server** 的工具白名单（每工具映射 `risk / roles / param_schema`）；顺手点"断开"做故障演练，看连接状态变化与自动重连
- **金句（背下来）**："**工具可以长在外部系统里（MCP），但能不能被调、由谁调、调完留什么痕，必须由我们的 Harness 说了算**——MCP 解决'连接'，我们解决'治理'。"

### 3.8 Trace · 审计回放（1 分钟）

- 打开该工单 Trace 页：模型/Provider、工具（含 MCP `context_source="mcp"`）、状态变化、延迟一屏可见
- 讲点：每次模型调用与工具调用都落库，含**模型版本、提示词版本、上下文来源、参数、结果、状态前后、耗时**——出问题能精确回放是哪一步

### 3.9 指标 · 监控评估（40 秒）

- 打开 `/metrics`（`GET /api/governance/metrics`）：成功率/正确失败率/延迟/成本/人工接管率
- 讲点："人工接管率"是 harness 特有指标：它反映系统把多少决策正确地还给了人

### 3.10 收尾 · 可演进性（1 分钟）

"M1–M5 五个里程碑全部完成（骨架 → Harness 内核 → 前端/知识库/部署 → OpenAI Agents SDK → MCP 集成），架构高并发加固阶段 1 也已落地（2026-08-17）。这套现在单机跑，但可演进：切模型只改配置、上 K8s 把状态外置、要 PG 有迁移点。**今天演示的是最小闭环，但它每一层都能在生产里找到对应物。**"

**演示冷启动兜底**：不配 `OPENROUTER_API_KEY` 且 Ollama 不可达时，Agent 链路自动走离线 `reader` 后端，HITL/Trace/指标/MCP 白名单照常演示，保证面试现场不翻车。

## 5. 追问与 QA 预案

### Q1：为什么不用 LangGraph / AutoGen 这些 Agent 框架？

答："LLM 循环我用官方 **OpenAI Agents SDK**（工具循环/多 Agent handoff 是它擅长且成熟的部分），但**企业治理层**（状态机/审批/预算/审计）我保留自研，不交给通用编排框架的黑盒。为什么不全用 LangGraph？因为它把 checkpoint/interrupt/HITL 做成黑盒，我自研的状态机 + SDK 原生 interruptions，每一行都能讲清'HITL 怎么中断、又怎么恢复'。**Agent 的动作序列必须由确定性 Workflow 管理，防止跳步/重复；LLM 只负责判断，执行权在 Harness。**"

### Q2：如何防止提示注入 / Agent 越权？

答：三层防护——

1. 工具结果按 content 类型处理，不把工具输出里的指令当系统指令
2. 工具参数进强类型校验，非法直接拒
3. 工具**白名单**注册表，模型只能调用已登记工具（落点：`app/skills/registry.py` 的 `invoke` 未知工具即拒绝）
   （MCP 工具的"未声明即拒绝"是同一原则的延伸，见 Q11。）

### Q3：上下文越来越大怎么办？（Auto-Compact）

答："我实现了三件事：选（只带这一圈需要的）、压（长 observation 先压缩）、截（超阈值把早期历史压成一段摘要，给关键状态留空间）。代码在 `app/context_assembler.py` 的 `assemble` / `_auto_compact` / `_compress_obs`。"

### Q4：HITL 中断/恢复不是会丢上下文吗？

答："不会。M4 起用 SDK 原生 interrupts：模型调用高危工具 → `RunResult.interruptions` 得到 `ToolApprovalItem`，我把参数写进 `approvals` 表并把整个 `RunState` 存进内存注册表（另序列化到 `approvals.run_state_json` 支持跨进程恢复），工单转 `awaiting_approval`。审批通过后 `state.approve(item)` 再 `Runner.run_sync(agent, state)` **从同一 run 继续**（含已发生的多 Agent handoff），不重跑整轮。"

### Q5：模型想调用一个不存在的工具怎么办？

答："`registry.invoke` 第一个判断就是工具是否登记，未登记直接返回**失败**并拒绝执行。测试 T08 专门覆盖'幻觉工具被拒'。"

### Q6：如何验证 Agent 没跑偏 / 预算失控？

答："双重保险：状态机约束动作序列不能跳步；三重预算（步数/Token/时间）每步 `consume_step` 触顶即 `failed` 终止。回合收敛时还要模型输出 `done:true` + 规则校验器确认产物完整性，随后进入 `pending_confirm` 等客户确认。"

### Q7：多租户怎么做隔离？

答："所有数据表带 `tenant_id`，查询强制加租户条件（`list_tickets` 按租户过滤，越权 403）；工具装配按角色过滤（`tools_for_role`）。这是**物理隔离**，不依赖模型自觉。"

### Q8：模型怎么切换？OpenAI 兼容是什么？

答："M4 起主用 **OpenRouter**（OpenAI 兼容 `/v1/chat/completions`）⇄ 兜底 **Ollama**（同一协议）⇄ 离线 **reader** 三级降级：OpenRouter 失败自动切 Ollama，均不可用回退 reader（保证演示不翻车）。SDK 侧用自定义 `RouterProvider` 按模型名前缀（`openrouter:`/`ollama:`）路由；`.env` 里按场景设主/兜底键（`AGENT_MODEL` / `AGENT_FALLBACK_MODEL`、`CLASSIFIER_MODEL` / `CLASSIFIER_FALLBACK_MODEL`、`RELEVANCE_MODEL` / `REWRITE_MODEL` 等，完整清单见 [配置清单.md](../03-部署运维/配置清单.md)）。注意：旧文档说的 `MODEL_PROVIDER`/`OPENAI_API_KEY` 等键已移除，不是现行配置。"

### Q9：数据敏感信息怎么办？

答："`masker.py`：姓名→`张*`、邮箱→`z****@corp.com`、密码/令牌→`***`。工具返回值（含 MCP 输出）先脱敏再喂回模型，模型不会拿到明文凭证；`/api/mcp` 配置接口同样对 headers/密钥脱敏。"

### Q10：为什么是这种 Demo 而非通用聊天 Agent？

答："因为我要展示的不是'模型能力'，而是**工程能力**——**把大模型安全接进企业业务的能力**，这才是 AI 开发工程师的核心竞争力。"

### Q11（新增）：MCP 工具的安全边界是什么？「未声明即拒绝」怎么理解？

答："MCP server 暴露的工具**不会自动放行**——`app/mcp/config.py` 按 `mcp_servers.json` 的映射表（工具名 → `risk/roles/param_schema`）装配，**未声明的工具默认拒绝**（防工具全量放行）；`param_schema` 用 JSON Schema 子集严格校验（`additionalProperties:false`），非法参数拒绝执行并落审计；映射 `risk=high` → `needs_approval=True`，直接复用 SDK 原生 HITL 审批；调用全程走治理链（预算 → 幂等去重 → 调用 → tool\_calls 落库 / trace `context_source="mcp"` / ticket\_events → 脱敏 → 返回）。降级时**只放行非 high**：MCP 不可用，低/中风险工具降级为'拒绝并说明'，高风险工具保持不可用——宁可失败不越权。"

### Q12（新增）：MCP 和你自己的函数调用（function calling）什么关系？

答："两条线，但**同一条治理链**。自研工具（`app/skills/registry.py`）是硬编码注册表，模型调 `search_kb`/`query_user_dir`/`grant_db_readonly`；MCP 是**外部工具标准协议**（stdio / streamable\_http），解决'工具长在外部系统里'（CMDB、GitHub）。`app/mcp/bridge.py` 把 MCP 工具包装成 SDK `FunctionTool`（`params_json_schema` 取 MCP 原始 schema），`on_invoke` 执行体与 `app/agents_tools.py:_run` **同构**——预算/去重/落库/trace/脱敏/审批完全一致。所以 MCP 是'工具面的加法'：连接协议不同，治理标准相同。"

### Q13（新增）：为什么不用 LangGraph？（追问变体）

答："核心矛盾是**治理可见性**：LangGraph 把 checkpoint/interrupt/HITL 做成黑盒，面试里我能讲清楚'我的 HITL 怎么中断、怎么恢复'是因为它是自研状态机 + SDK 原生 interruptions 拼出来的；其次 LangGraph 是 DAG 思维，而我的工单循环是**有状态的状态机**（含客户确认态、审批恢复路径），显式 `TRANSITIONS` 表反而更直白。LLM 循环这种'不该重复造轮子'的部分我交给官方 SDK，治理层'必须逐行可讲'的部分我自研——各取所长。"

### Q14（新增）：单机 SQLite 够用吗？什么时候上 PostgreSQL？

答："当前够用，且做了针对性加固：WAL + `busy_timeout` + `synchronous=NORMAL` 提升读并发；状态机转移用 `UPDATE ... WHERE id=? AND status=?` **乐观锁**防竞态；`app/taskqueue.py` 每工单互斥锁 + worker 池把 Agent 长任务挪出 HTTP 线程。**什么时候上 PG**：多副本部署（乐观锁已有，SQLite 文件锁撑不住多进程写）、审计查询/写入放大上来之后、需要在线备份与角色权限时。迁移点是现成的——数据访问全部收敛在 `app/daos/*`，换库只改 DAO 层与 `app/db.py`，不碰编排逻辑。"

### Q15（新增）：为什么回合收敛后还要 `pending_confirm` 客户确认，不能直接 done？

答："**收敛 ≠ 完成**：Agent 输出 `done:true` 只代表'它认为自己处理完了'，不代表业务上'客户认可'。我把它拆成两个状态：`pending_confirm`（待客户确认）→ 客户点确认 → `done`。职责分离：**审批管'能不能做'（operator/admin 决策权），确认管'做完了吗'（工单发起人决策权）**，防止 Agent 自说自话地关单。这也是 harness 区别于聊天机器人的业务闭环设计。"

### Q16（新增）：完全离线怎么演示？

答："三级降级最后一级是离线 `reader` 后端——不配 `OPENROUTER_API_KEY`、Ollama 不可达时，Agent 链路自动走 reader，HITL/审批/Trace/指标照常走通。确定性验证靠离线脚本：`scripts/run_all_tests.py`（全分支离线组）、`scripts/smoke_mcp_core.py`（26 断言，本地 stdio 子进程，不依赖真模型）、`scripts/eval_rag.py --compare`（无 embedding/rerank 时自动降级关键词路）。真模型脚本（`smoke_agents.py`/`smoke_mcp.py`）作为可选加分项。"

### Q17（补充）：rerank 不可用怎么办？

答："`app/rerank.py` 实现'探测一次 + 优雅降级'：主用 OpenRouter `/api/v1/rerank` → Ollama 探测（主线 ≤0.32.x 无原生 rerank 端点则 404 回落）→ 均不可用保持 RRF 顺序（标记 `skipped`），**绝不中断检索链路**。召回侧先放大 `RERANK_RECALL_FACTOR`（默认 4）倍再精排取 top\_k，rerank 失效时损失可控。"

### 5.x 深挖层（面试官可能追问到代码）

**幂等**：每个高危工具生成 `idempotency_key = fingerprint(ticket, tool, params)`；`guards.is_duplicate` 查 `tool_calls` 表：同参数时间窗内已成功 → 拦截（M5 修复了时间窗比较的时区/格式 bug，本地与 MCP 工具同受益）。恢复执行不会重复下发权限；失败有补偿工具 `revoke_db_readonly`。

**状态机为什么这么设计**：`app/state_machine.py` 的 `TRANSITIONS` 是显式映射，"禁止跳步"在 `transition()` 里硬校验；每次转移写 `ticket_events` 审计（from/to/actor/reason）。审批恢复路径明确要求 `awaiting_approval → gathering → agent_running → pending_confirm`，不允许直跳。

**模型路由策略**：`model_router.route(intent, risk)`：知识 → 轻量，变更/故障 → 强模型，高风险升格（`ROUTER_MODEL_HIGH_RISK`）。

**预算的实现细节**：`budget.consume_step(tokens)` 每步自增并 `check()`，超 `BUDGET_MAX_STEPS/BUDGET_MAX_TOKENS/BUDGET_MAX_SECONDS` 抛 `BudgetExceeded`；orchestrator catch 后工单转 `failed`，不会无限循环。

### 5.y 如果被问到"项目中最大的难点/收获"

> "最大的难点不是让模型回答问题，而是**把'不可控'的 Agent 变成'可控'的流程**。最大的收获是理解到：企业级 Agent 的工程重心在 harness——权限、审批、预算、审计——而不是模型本身。这也是我为什么自研状态机而不是套框架：只有自己写的，才敢在面试里逐行讲清楚它是怎么保证可靠、可控、可审计的。"
