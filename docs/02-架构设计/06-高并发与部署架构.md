## 1. 部署拓扑（当前，单机）

```
Browser
   │  HTTPS(80)
   ▼
Nginx（唯一入口，/ → web:3000，/api → app:8000；WS 升级头 + proxy_buffering off）
   ├─ web  (Next.js 静态代理，Docker)
   └─ app  (uvicorn 单 worker，FastAPI，Docker)
        ├─ SQLite data/app.db（WAL + busy_timeout=5000 + synchronous=NORMAL）
        ├─ LanceDB data/vector-kb
        └─ MCP 子进程（cmdb stdio）/ 外部 streamable_http（github）
```

- `docker-compose.yml`：开发拓扑（expose 8000/3000 + 80:80）；`docker-compose.prod.yml`：生产拓扑（`127.0.0.1:8001:8000` / `127.0.0.1:3000:3000` 仅本机可达，主机 nginx 反代）；
- 部署脚本：`scripts/deploy.sh`；生产账户：`scripts/init_prod.py`（`APP_ENV=production` 禁用演示 seed）；
- CI：`.github/workflows/deploy.yml`（push main → SSH 部署阿里云；**docs-check job 校验文档，失败阻断部署**）。

## 2. 并发模型（阶段 1 落地后）

| 维度 | 机制 | 防的问题 |
|---|---|---|
| Agent 长任务 | `app/taskqueue.py` worker 池（`AGENT_WORKERS=4`）——run/追问/审批**入队即返回** `{"status":"queued"}` | HTTP 线程池被 40–200s 长任务占满 |
| 每工单并发 | `try_acquire` 非阻塞互斥锁（run 与追问、双 run 互斥，第二次 409） | 同一工单双跑 |
| 跨进程竞态 | `daos.transition` 乐观锁（`UPDATE ... WHERE status=?`） | 多副本部署状态竞争 |
| LLM 压力 | `BoundedSemaphore`（`AGENT_LLM_CONCURRENCY=4`）+ 单请求超时 60s | 慢响应拖垮 worker |
| 实时通道 | WebSocket `/api/tickets/{id}/ws`（拉模式 0.3s）+ 前端 2s 轮询兜底 | 事件增量获取；SSE 已 deprecated |
| 读放大 | 工单列表分页/筛选（`{items,total,page,page_size,pages}`） | 全量返回渲染卡顿 |

## 3. 阶段 2/3 路线图（未实施，roadmap）

| 阶段 | 方向 | 内容（出自历史评估） |
|---|---|---|
| 2 | 架构扩展 | PostgreSQL（写并发）、Redis（缓存/分布式锁/审批状态）、Agent 执行独立 worker 服务、JWT + 刷新/撤销、SSO 对接 |
| 3 | 多副本与弹性 | K8s 化、消息队列（任务分发）、可观测体系升级（链路追踪接入） |

> 演进叙事：**当前单机方案把「长任务不占请求线程」做对了，换 PG + Redis + 独立 worker 服务即可平滑升级**——架构上不欠债。
