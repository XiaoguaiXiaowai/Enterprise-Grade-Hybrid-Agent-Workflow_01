# 治理层设计（预算 · 守卫 · 工具白名单 · HITL · 幂等）

> 状态：现行 · 最后校验：2026-08-18 · 校验方式：符号级 + 行为实测
> 一句话：治理层是「可靠/可控/可审计」的全部落地——**模型只负责判断，执行权交给确定性的流程、权限与审批**。
> 代码入口见 [能力-代码映射表.md](../01-核心功能/06-能力-代码映射表.md) ③④⑤⑧。

---

## 1. 治理四件套总览

| 治理 | 模块 | 防的是什么 | 触顶/违规后 |
|---|---|---|---|
| 三重预算 | `app/budget.py` | 跑飞（步数/Token/时间无限消耗） | `BudgetExceeded` → `failed(budget)` + 正确失败率计 |
| 守卫 | `app/guards.py` | 重复执行（同参幂等）、停不下来 | 同参时间窗内已成功 → 拦截；计划含停止词 → 终止 |
| 工具白名单 | `app/skills/registry.py` + `app/agents_tools.py` | 幻觉调用、越权调用 | 未注册/角色不符 → 拒绝并记录 |
| 审批 HITL | `app/daos/approvals.py` + SDK 原生中断 | 高风险变更失控 | `awaiting_approval` 挂起，审批通过才恢复 |

## 2. 预算（三重约束，`app/budget.py`）

`Budget(steps, tokens, seconds)` 三把尺子，任何一把触顶即 `BudgetExceeded`：

- `BUDGET_MAX_STEPS=25`（默认）——LLM 循环步数；
- `BUDGET_MAX_TOKENS=200000` —— 累计 token；
- `BUDGET_MAX_SECONDS=600` —— 墙钟时间。

设计要点：预算在进程启动前由 env 注入（`app/config.py` 实例化时读取）；触顶由 orchestrator 捕获后置 `failed` 并计 `correct_failure`（预期内失败，区别于模型乱来的失败）。

## 3. 守卫（幂等与停止，`app/guards.py`）

- `fingerprint(scope, tool_name, params)` —— 参数规范化指纹；
- `is_duplicate(ticket_id, tool_name, params)` —— `DEDUP_WINDOW_MINUTES=5` 窗口内同指纹已成功（`tool_calls` 表 status=done）即判重复 → 拒绝；时间窗用 UTC 对齐（M5 修复）；
- `should_stop(plan_text)` —— 计划文本含停止条件词即终止。

## 4. 工具白名单与 RBAC 过滤

- **注册即白名单**：`@register_tool(name, risk, roles, description)`（`app/skills/registry.py`）；未注册工具被调用 → 直接拒绝（幻觉防护）；
- **角色过滤**：`tools_for_role(role)` 决定每个角色「看得见」的工具集；SDK 装配时 `build_agent_tools(role, names)` 只装可见工具，执行时 `_run` 内再复查一次（双保险）；
- **参数强校验**：skill 函数内校验 + MCP 工具用 JSON Schema（`additionalProperties:false`）；
- **脱敏**：`app/skills/masker.py`（`mask_principal`/`mask_secret`）在结果落库/trace 前打码。

## 5. HITL 审批闭环（人机协同）

```
高风险工具被请求
   │  risk=high → function_tool(needs_approval=True)
   ▼
SDK 原生中断（interruptions）→ 审批单落库（approvals 表 + run_state_json 快照）
   │
   ▼
审批台 approve / reject（POST /api/tickets/{id}/approve，operator/admin）
   │
   ├─ approve → agents_runner.resume_run 恢复同一 run（经 gathering→agent_running→pending_confirm）
   └─ reject  → 审批单置 rejected；模型调整方案后收敛或再次申请（不直接 cancelled）
```

设计要点：

- **恢复可跨进程**：`run_state_json` 持久化 RunState，`_resume_from_db` 支持进程重启后恢复（P2-11），不依赖内存 `_PENDING`；
- **防重复申请**：审批通过后 `_walk_transitions` 走完整路径，状态机保证不跳步；
- **补偿语义**：`revoke_db_readonly` 作为变更补偿工具，同样 high risk 需审批；
- **权限落库**：grant 状态 SQLite 持久化（`app/skills/grant.py`），非内存态，重启不丢。
