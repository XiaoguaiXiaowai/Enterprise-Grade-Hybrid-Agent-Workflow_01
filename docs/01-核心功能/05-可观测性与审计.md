# 可观测性与审计（Trace · 指标 · 日志）

> 状态：现行 · 最后校验：2026-08-18 · 校验方式：符号级 + 行为实测
> 一句话：**每一步都能回答「为什么」**——业务 Trace 回放、监控指标、函数级日志三层互补。
> 代码入口见 [能力-代码映射表.md](06-能力-代码映射表.md) ⑥⑦。

---

## 1. 三层可观测体系

| 层 | 载体 | 回答的问题 | 谁消费 |
|---|---|---|---|
| 业务 Trace | SQLite `traces` 表 + `/api/governance/traces/{id}` | 这一单发生了什么（模型/提示词版本/工具/状态/延迟） | 前端 Trace 回放页 |
| 监控指标 | SQLite `metrics` 表 + `/api/governance/metrics` | 系统整体健康度（成功率/成本/延迟） | 前端指标看板 |
| 函数级日志 | `logs/` 文本文件（`APP_LOG_LEVEL` 开关） | 实时调试：每次操作执行了哪些 py 函数 | 开发者 grep |

## 2. 业务 Trace（全链路回放）

**写入**（两条路径，同一张 `traces` 表）：

- 传统网关路径：`app/trace.py:write(req_id, ticket_id, model, provider, prompt_version, tool_name, ...)`，由 `app/orchestrator.py`（`_plan_and_execute`/`_execute_tool`）在模型调用与工具调用时写入；
- SDK 路径：`app/agents_trace.py` 的 `LocalTraceProcessor`（`TracingProcessor` 子类）把 OpenAI Agents SDK 顶层 Trace/span 转存 SQLite，`install()` 在 orchestrator 导入时挂载；span 类型含 agent / handoff / generation。

**字段**（`app/trace.py`）：`model`、`provider`、`prompt_version`（SDK 路径为 `M4-agents`）、`tool_name`、`context_source`、`state`、延迟与重试等。

**回放**：

```bash
# 先跑一单（scripts/smoke_m2.py 或 API 建单+run），再查：
curl -s localhost:8000/api/governance/traces/1 -H "X-Auth-Token: <token>"
```

前端 `web/app/traces/[id]/page.tsx` 一屏展示：模型版本 / 提示词版本 / 工具调用 / 状态转移。

**事件审计**：`ticket_events` 表逐条记录（`app/daos/tickets.py:add_event`），事件类型（grep 实测）：

`created` `stage`（快速落单流水线阶段）`rewrite` `classify` 相关、`model_call` `tool_call` `hitl` `deliver`、`system_message` `user_message`、`confirmed` `closed` `cancelled` `reject_followup`、`log` 等——与 `traces` 表互补：events 存业务时序，traces 存模型/工具调用明细。

## 3. 监控指标（成功率/正确失败率/延迟/成本/人工接管率）

`app/metrics.py`：

- `record(ticket_id, *, success, correct_failure, latency_ms, cost, human_takeover)` —— 每单收敛时由 `orchestrator._record_metrics` 落库；
- `aggregate` / `aggregate_range` / `daily_series` —— 按天聚合与区间查询；
- 口径：**正确失败率** = 拒绝危险操作等「预期内失败」占比（区别于模型乱来导致的失败）；**人工接管率** = 进入 HITL 审批的比例。

```bash
curl -s "localhost:8000/api/governance/metrics?days=7" -H "X-Auth-Token: <token>"
# 返回字段：success_rate / correct_failure_rate / human_takeover_rate / avg_latency_ms / total_cost ...
```

前端 `web/app/metrics/page.tsx` 看板。

## 4. 函数级调用日志（实时调试）

- 开关：`.env` 中 `APP_LOG_LEVEL=info`（`off` 关 | `info` 记录请求路由+核心函数进入/退出 | `debug` 预留扩展）；目录 `LOG_DIR`（默认 `logs/`），按日期累加。
- `app/tracelog.py:trace_call` 装饰核心函数，输出格式：

```
[10:15:03]  TRACE  enter  orchestrator._run_loop
[10:15:03]  TRACE  exit   orchestrator._run_loop  ok
[10:15:03]  REQUEST  POST  /api/tickets  ->  api.tickets.create_ticket
```

- 集中式异常：`log_exception` 统一捕获并记录异常上下文（`app/tracelog.py:90`）。
