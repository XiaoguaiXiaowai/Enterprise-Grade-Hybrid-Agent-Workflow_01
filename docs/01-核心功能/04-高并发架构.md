# 高并发架构（后台任务化 · 防双跑 · 分页）

> 状态：现行 · 最后校验：2026-08-18 · 校验方式：符号级 + 行为实测
> 一句话：**Agent 长任务不再占 HTTP 线程**——run/追问/审批入队即返回，worker 池执行；配合每工单互斥锁、乐观锁、SQLite 调优与分页，单机即可扛住「大量用户同时建单」。
> 背景评估与阶段 2/3 路线图见 [高并发与部署架构.md](../02-架构设计/高并发与部署架构.md)；历史评估报告在 [99-归档/架构评估与改善方案.md](../99-归档/架构评估与改善方案.md)。

---

## 1. 问题背景

改造前：`POST /api/tickets/{id}/run` **同步阻塞**，整个 Agent 循环（40–200 秒）在 HTTP 请求线程内跑完才返回。FastAPI 同步端点跑在线程池（默认 40 线程）→ 40 个用户同时建单 = 线程池占满 → 登录、列表、轮询全部排队，系统「卡死」。

## 2. 阶段 1 五项整改（已全部实施，2026-08-17）

### 2-1 Agent 后台任务执行器（最致命风险）

`app/taskqueue.py`：run/追问/审批端点只做**校验与入队**，立即返回 `{"status":"queued"}`；Agent 循环由 worker 线程池执行（`AGENT_WORKERS`，默认 4，Agent 并发封顶，LLM/DB 压力可控）。事件照常写 DB，前端 WS（拉模式 0.3s）/轮询自然拿到增量，**前端零改动**。

| 函数 | 职责 |
|---|---|
| `submit_ticket_job(ticket_id, fn, *args)` | 入队并绑定工单 |
| `try_acquire(ticket_id)` | 每工单非阻塞互斥锁（防并发双跑：run 与追问、双 run 等） |
| `release(ticket_id)` | 执行体 finally 释放 |
| `can_mark_failed(status)` | 异常兜底：状态机允许则置 `failed` + `system_message` |

### 2-2 状态机乐观锁（防竞态）

`app/daos/tickets.py:transition` 用 `UPDATE ... WHERE id=? AND status=?` 条件更新，rowcount≠1 抛 `InvalidTransition`（进程内还有 taskqueue 互斥锁兜底；多副本部署依赖该乐观锁）。

### 2-3 SQLite 调优

`app/db.py`：WAL 模式 + `busy_timeout=5000` + `synchronous=NORMAL`（读并发提升，写串行可控）。

### 2-4 前端轮询降频

`web/app/tickets/page.tsxx`：状态轮询 2s（原 1s）；状态变化即时刷新 + 每 10 次（≈20s）兜底刷新。

### 2-5 LLM 并发闸门

`app/llm_gateway.py`：`BoundedSemaphore`（`AGENT_LLM_CONCURRENCY`，默认 4）+ 单请求超时（`AGENT_LLM_TIMEOUT`，默认 60s），防 LLM 慢响应拖垮 worker。

## 3. 分页与列表优化（P1）

- 后端：`GET /api/tickets?page=&page_size=&status=&q=` → `{items, total, page, page_size, pages}`（`app/daos/tickets.py:list_tickets(limit, offset, q, statuses)` + `count_tickets`）；
- 前端：`listTicketsPaginated` + 上一页/下一页翻页 + 搜索防抖 300ms 回第 1 页 + 删空自动回退页（`web/app/tickets/page.tsxx`）。

## 4. 快速落单（P0）

建单不再同步跑完整分类流水线：`create_ticket` 最小校验即建单（秒回）；`relevance_check → rewrite_content → classify` 移到 run 阶段的 `_entry_stages` 流水线（`app/orchestrator.py`），以 `stage` 事件流式推送进度；相关性不通过 → `cancelled` + 拒绝文案。

## 5. 验证方式

| 验证项 | 命令 | 模式 |
|---|---|---|
| run 入队即返回 | `POST /api/tickets/{id}/run` 响应 `{"status":"queued"}` | 🔌 |
| 并发双跑拦截 | 对同一工单连发两次 run，第二次被 `try_acquire` 拒绝（409） | 🔌 |
| 分页契约 | `curl "localhost:8000/api/tickets?page=2&page_size=10"` 返回 `{items,total,pages}` | 🔌 |
| 全分支回归 | `python scripts/run_all_tests.py`（offline 组） | 🔌 |
| 异常兜底 | 观察 worker 执行抛异常后工单置 `failed` + `system_message` | 🔌 |
